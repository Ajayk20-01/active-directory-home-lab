# ServiceNow – Incident Management and Ticket Handling

## 1. Project Overview

This project covers IT Service Management (ITSM) concepts and incident management workflows commonly used by IT Support and Service Desk teams.

The objective is to understand incident creation, categorization, prioritization, assignment, troubleshooting, resolution and closure.

## 2. ITSM Concepts

| Term | Description |
|---|---|
| Incident | Unplanned interruption or reduction in service quality |
| Service Request | Request for a standard IT service |
| Problem | Investigation of the underlying cause of incidents |
| Change | Controlled modification to an IT service |
| SLA | Service Level Agreement |
| TAT | Turnaround Time |

## 3. Incident Priority

| Priority | Description | Example |
|---|---|---|
| P1 - Critical | Major business impact | Company-wide network outage |
| P2 - High | Significant business impact | Department-wide application outage |
| P3 - Moderate | Limited business impact | One user's Outlook issue |
| P4 - Low | Minor impact | General software assistance |

Actual priority depends on the organization's impact and urgency matrix.

## 4. Incident Lifecycle

1. New – Incident is reported.
2. Assigned – Ticket is routed to the responsible team.
3. In Progress – Support engineer investigates the issue.
4. Resolved – A solution is implemented and documented.
5. Closed – Incident closure is completed according to company policy.

## 5. Simulated Incident Scenarios

### Scenario 1: Outlook Not Sending Emails

**Category:** Software

**Short Description:** Outlook not sending emails.

**Impact:** Limited to one user.

**Priority:** P3, subject to the organization's priority matrix.

**Assignment Group:** IT Service Desk.

**Troubleshooting:**

- Checked internet connectivity.
- Reviewed Outlook connection status.
- Inspected the Outbox folder.
- Investigated account configuration.

**Resolution:** Document the actual cause and successful fix.

### Scenario 2: User Unable to Log In

**Category:** User Administration

**Short Description:** User unable to access Windows account.

**Priority:** Determine based on business impact and urgency.

**Assignment Group:** IT Support.

**Troubleshooting:**

- Verified user identity.
- Checked account status.
- Investigated password-related issues.
- Checked account lockout status.

**Resolution:** Record the actual account recovery action performed.

### Scenario 3: Network Connectivity Issue

**Category:** Network

**Short Description:** User unable to access network resources.

**Priority:** Determine based on the number of affected users and business impact.

**Assignment Group:** Network Support.

**Troubleshooting:**

- Checked IP configuration.
- Tested network connectivity.
- Verified DNS settings.
- Investigated gateway connectivity.

**Resolution:** Document the actual root cause and fix.

## 7. IT Support Best Practices

- Record accurate incident descriptions.
- Select appropriate categories.
- Assign priority based on impact and urgency.
- Route tickets to the correct support team.
- Maintain clear work notes.
- Communicate updates to users.
- Follow SLA requirements.
- Verify the issue is resolved before closure.
